Local Minikube deployment: practice-1 — run commands one by one

Cluster/profile: practice-1
Application namespace: task-board
These commands are for you to run; no cluster has been started by creating this file.

1. Go to the project directory:
cd ~/RISHAV/deploy-test-1

2. Start or reuse the Minikube cluster:
minikube start -p practice-1 --driver=docker

3. Build the backend image:
docker build -t tasks-backend:local ./backend

4. Build the frontend image:
docker build -t tasks-frontend:local ./frontend

5. Load both images into Minikube:
minikube -p practice-1 image load --daemon --overwrite=true tasks-backend:local
minikube -p practice-1 image load --daemon --overwrite=true tasks-frontend:local

6. Import your environment file into a Kubernetes Secret, then deploy:
# Run these commands yourself; do not share their generated Secret output.
kubectl --context=practice-1 create namespace task-board --dry-run=client -o yaml | kubectl --context=practice-1 apply -f -
kubectl --context=practice-1 -n task-board create secret generic database --from-env-file=backend/.env --dry-run=client -o yaml | kubectl --context=practice-1 apply -f -
# Remove the old local database if present. Its PVC is kept to preserve old data.
kubectl --context=practice-1 -n task-board delete deployment/postgres service/postgres --ignore-not-found
kubectl --context=practice-1 apply -f k8s/local.yaml

If updating an existing deployment with rebuilt images, restart its pods:
kubectl --context=practice-1 -n task-board rollout restart deployment/backend deployment/frontend

7. Wait for all Deployments to become ready:
kubectl --context=practice-1 -n task-board rollout status deployment/backend --timeout=300s
kubectl --context=practice-1 -n task-board rollout status deployment/frontend --timeout=300s

8. Check the pods (frontend/backend counts follow replicas in k8s/local.yaml):
kubectl --context=practice-1 -n task-board get pods

9. Forward the frontend to your laptop:
kubectl --context=practice-1 -n task-board port-forward service/frontend 8081:80

Keep this terminal open. Open http://localhost:8081 in your browser.
Ctrl+C stops forwarding, but leaves the application running.

10. Optional: open the Dashboard in another terminal:
minikube dashboard -p practice-1

Select the task-board namespace. Keep the Dashboard terminal open.

If localhost port 8081 is already in use, stop the previous port-forward with Ctrl+C, or use 8082:80 and open http://localhost:8082.

After changing backend/.env, rerun the Secret import and restart deployment/backend.
The env file must use KEY=value entries supported by kubectl; do not use export or shell expansion.
Use an unquoted DATABASE_URL value. Keep any provider-required SSL query parameters.
